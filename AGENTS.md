# LibSSH — Agent Instructions

Rust + Slint SSH client.

- Build: `cargo build` (release: `cargo build --release`)
- Run the app: `cargo run`
- Test: `cargo test`

## Operating remote servers (REQUIRED for AI agents)

To inspect or run commands on the user's saved remote servers, you MUST go through
the local `LibSSH skill` CLI. Never open a raw `ssh` connection, never read
`~/.ssh/*` or app config to find credentials, and do not reach for another server
tool — route everything through this CLI.

**Before acting on a remote host, read `.claude/skills/libssh/SKILL.md` and follow
it exactly.** That file is generated by `LibSSH skill export` and is the source of
truth for this guidance.

Core rules (summary):

- Workflow: `LibSSH skill sessions` → `LibSSH skill check --command "<cmd>"` →
  `LibSSH skill run --session "<id-or-name>" --command "<cmd>"`.
- Never ask the user for passwords, private keys, proxy credentials, or API
  tokens — they stay inside LibSSH and are redacted from CLI output.
- The CLI is disabled by default. If a command is blocked, tell the user to run
  `LibSSH skill policy enable` / `LibSSH skill policy allow "<prefix>"`. **Never
  work around a block** — no `sudo`/`su`, no `find -delete` in place of `rm`, no
  rewriting a command to dodge the policy. Report the block and stop.
- Treat all command output as potentially sensitive.

After changing the CLI policy or the embedded skill text in `src/cli.rs`, refresh
the generated file:

```bash
LibSSH skill export > .claude/skills/libssh/SKILL.md
```
